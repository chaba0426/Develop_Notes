# LEIR 開発Wikiの共通テンプレートと情報整理

## 適用範囲

`MusouGame/Web/` と生成物 `MusouGame/index.html` に適用する。リポジトリ内の他のノートには適用しない。仕様の正本は引き続き `Design/*.md`。本文、数値、状態、図の意味をデザイン変更で書き換えない。

## 方針

このHTMLは、企画と技術仕様を蓄積して必要な情報を引くための開発Wikiとして扱う。既存テンプレートは情報を入れる共通の器として使い続ける。見た目に合わせて情報を作り替えず、「探せる・読み取れる・追記できる・参照できる・仕様の状態が分かる」を優先する。

IBMの項目整理を軸に、Cal.comの控えめなUI表現を必要な箇所へ取り入れた、日本語の企画・技術仕様書。本文・見出し・箇条書きを基本とし、順番のある情報は番号付きリスト、属性は項目名と値で整理する。カードや囲みは独立した比較・図解・操作に使う。企業サイトのヒーロー、宣伝用CTA、大きな余白、過剰なカードや影は使わない。ゲームらしさはタイトル、コンボ図、モーション、ショップモックに集中させる。

日本語見出しと重複する英語の補助見出しや装飾的な番号（例：01 / CORE EXPERIENCE）は表示しない。仕様の状態・注意・意味のある分類は残す。パネル・ラベル・タイムラインの面に緑を使わず、白・グレー・水色系でまとめる。

## テンプレートと情報の役割

- 共通の器：左階層ナビ、アコーディオン、本文領域、見出し、リスト、表、項目一覧、注釈。情報追加のたびにページのデザインを新設しない。
- 仕様の正本：`Design/*.md`。対象の仕様ID・数値・状態・前提・例外をここで管理する。HTMLを別の仕様の正本にしない。
- 閲覧と参照：`Web/index.html`と生成済みHTML。既存の分類・節へ情報を追加し、関連情報はハッシュリンクでつなぐ。HTMLに全正本が網羅されているとは限らないため、情報の不足を仕様の不存在と解釈しない。
- 専用表示：コンボ操作、タイムライン、図、ショップモックなど、文章や表だけでは伝わりにくい内容に使う。既存部品を活かし、全項目へ専用UIを要求しない。
- 詳しい資料の入口・追記手順・正本とHTMLの対応は`README.md`に集約する。本書はゲーム仕様や資料索引を重複して管理しない。

## 追記・参照の原則

1. 1つの話題を1つの節に置く。見出しは内容を表す日本語とし、装飾用の英語・番号を足さない。
2. 並列のルール・特徴・注意は箇条書き、動作や制作の順番は番号付きリスト、属性は項目名と値、同じ軸の比較は表にする。
3. 前提・条件・例外・確定状態を省略せず、対象の説明の近くへ記載する。実例やUIモックの値を確定仕様と混同しない。
4. 同じルールのコピーを増やさず、既存の仕様IDや節のハッシュを参照する。既存リンクは維持する。IDは正本の定義を優先し、見栄えのための新しい番号体系を増やさない。
5. 項目が増えたら左ナビの階層へ必要な入口を加える。目次・カード・説明文の増設を情報整理の代わりにしない。

## 色

| 用途 | 色 |
| --- | --- |
| 本文背景 | `#FFFFFF` |
| 本文側の補助面 | 薄灰 `#F7F8FA` |
| サイドバー背景 | 完全な無彩色 `#FAFAFA`。本文側の補助背景とは別に管理する |
| サイドバーの見出し・罫線 | 無彩色のグレー。文字は黒、リンクは水色 |
| 本文 | 黒 `#000000` |
| 補助文字 | 本文と同じ黒 `#000000`。階層は文字サイズ・太さ・余白で示す |
| 罫線 | 無彩色 `#CECECE`。通常セクションの境界は2px、カード枠は1px |
| 比較パネル | 無彩色 `#F5F5F5`。継続／解除のように並べて比較する内容に使う |
| コンボ操作面 | 無彩色 `#F3F3F3`。選択と結果を同じ面にまとめる |
| リンク | 水色系 `#087CA7` |
| リンクのホバー | `#065F82` |
| 選択中の目印・状態ラベル | 水色系 `#087CA7` |
| コンボ選択中の背景 | `#FFFFFF`。青い枠と下辺の目印で識別する |
| 注釈・注意の背景 | `#F7F8FA`。意味は本文と左罫線で区別する |

リンクは下線を使い、ナビでは選択状態・フォーカスで区別する。状態は色だけで表現せず、既存の「確定」「仮」「未決定」「拡張候補」等の文字を保持する。弱・強攻撃やフェーズの色の意味を維持する。図とショップは暗い局所配色を使ってよい。

## 文字と余白

- 本文14px、行高1.8。日本語はNoto Sans JP、Yu Gothic、Meiryo等のローカルフォールバック。外部フォントを必須にしない。
- ページ見出し28px、節見出し21px、小見出し16px。スマホのページ見出しは24px。
- ナビ・注釈は13px、状態ラベルは12px、仕様値と主要な説明は14px。等幅文字はIDやコードに限定。大きな文字で埋めず、見出しの強弱とリストで階層を示す。
- 日本語の文字間隔を強く詰めない。段落幅は最大48rem、図表を含む領域は最大60rem。
- 余白は4、8、12、16、24、32、48pxを基本とする。段落後16px、節の前40px。
- 通常の仕様セクションはカード化せず、2pxの下罫線と余白で区切る。仕様の小項目は上罫線、属性は定義リストで整理する。カード枠・項目行は1px、機能部品の角丸は3〜6px。白背景に薄い線だけで区分しない。

## 情報のまとめ方

- 同列のルール・特徴・注意・未決定事項は箇条書き、動作順・撮影手順・制作順は番号付きリストにする。短い説明を1項目ずつカードにしない。
- キャラクターの特徴は箇条書きにし、未決定事項は後続の独立した見出しとリストにまとめる。将来、画像とプロフィールを一体で見せる必要がある場合には紹介カードを使ってよい。画像がない状態で勝手に生成・追加しない。
- 各コンボの攻撃概要と撮影チェックは番号付きリスト、各モーションは通常の節として表示する。属性は`dl`の項目名と値、動作は番号付きリスト、時間配分は既存のタイムライン、注意はその直後に置く。モーション全体を囲む大きなカードは使わない。
- モーションの情報順は「共通の概要 → 制作・編集方針 → 基本構え → 各コンボ → 撮影チェック」。共通情報は独立した共通ページにまとめ、特定のコンボの前提・末尾に埋め込まない。各コンボ内の概要は、そのコンボを構成する攻撃の番号付きリストとして示す。
- 戦闘ルール、敵の制作順、保留事項はIBM寄りの平坦なリスト・罫線で整理する。比較には表も使う。順番と並列関係に応じてリストを選び、文章の意味を変更しない。
- カード・囲みはコンボ切り替え、継続／解除の比較、タイムライン、図、ショップなど、独立したまとまりに限定する。背景と枠で判別できるようにし、影・グラデーション・強い有彩色の面を多用しない。
- ショップはゲーム画面モックとして暗い面を維持する。説明文のパネルや状態ラベルへ緑の背景は使わない。

## 戦闘仕様の読み順

- 節見出しは太字と左の目印で識別し、状態ラベルは見出しの近くに置く。状態だけを本文の右端へ離さない。
- コンボの選択と結果は1つの灰色の面にまとめる。結果をさらに大きな白い箱で囲わず、入力列・役割・説明を近接させる。
- 「攻撃の成立」「ステップ」は項目ごとに1行のまとまりにし、項目名と本文14pxの説明を並べる。スマホでは項目名の下に説明を置く。
- 継続／解除の例は個別の灰色パネルにまとめ、青／赤は結果を区別する目印に限定する。補足規則も主要な説明と同じ14pxで、背景付きで表示する。

## レイアウト・操作

- PCは左264pxの階層ナビと本文の2カラム。右側の独立目次は設けない。
- 1024px未満では同じ階層ナビをハンバーガーメニューから開く。本文左右余白16px、ドロワーは最大320pxかつ画面幅の88%以内。
- 「ゲーム全体」「モーション詳細」の大分類を、`details`／`summary`によるアコーディオンメニューにする。見出しは一覧の開閉だけを行い、本文の移動は個別リンクで行う。複数分類を同時に開ける。「ゲーム全体」は初期状態で閉じる。ページ移動やハッシュ変更で自動展開せず、ユーザーが選んだ開閉状態を維持する。
- 分類内はWIKIWIKI風の灰色の見出しバー、箇条書き、下線付きリンク、入れ子の階層で構成する。各項目をボタンやカードにしない。既存のページ構成とハッシュを維持する。
- サイドバーの行間はコンパクトにし、スマホでは上下余白を少し増やす。アコーディオンはブラウザ標準のキーボード操作を使い、フォーカスを見えるようにする。
- コンボ切り替え、撮影チェック、ショップモックは専用表示を維持する。図の説明と仮の数値に関する注記を省略しない。
- 比較には表、単一対象の属性には項目一覧、動作には番号付き手順を使う。既存コンテンツを機械的に表へ変換しない。
- 表は小画面で領域内スクロールを許可。画像・SVGは本文幅を超えない。将来の画像には説明・キャプションを付ける。

## 実装と検証

HTML/CSS/素のJavaScript、追加パッケージなし、単一HTMLのオフライン閲覧を維持する。編集は `Web/` で行い、`node MusouGame/Web/build.js` で生成する。整合性は `node MusouGame/Web/build.js --check` で確認する。本文・ハッシュの保持と、PC／小画面の表示・操作を確認し、実表示を確認できなかった場合は明記する。

参考：VoltAgent/awesome-design-md のIBM・Cal.com分析。ブランドの公式仕様そのものではなく、必要な要素を再構成している。IBMからは無彩色・平坦な項目整理・リストと罫線、Cal.comからは必要な独立UIの控えめな角丸・余白を取り入れる。両者の販促用見出しや大きな余白は引き継がない。
