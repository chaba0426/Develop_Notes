# 草原ステージ 要件整理（Codex A 引き継ぎ用）

- 対象作品：LEIR（仮）／3D無双系アクション・部屋攻略型ローグライト
- ステータス：企画要件の整理版（詳細設計・Goal実行仕様ではない）
- 更新日：2026-11-05
- 方針：決定済みの体験・景観を優先し、細部の美術表現・技術仕様は制作時に調整する

## 1. 目的と前提

本作は多数の敵を集め、剣のコンボで一気になぎ倒す爽快感を重視する3Dアクションゲーム。ステージは複数必要であり、**草原ステージと遺跡ステージを別々に制作**する。

最初は草原の戦闘部屋1つを制作し、戦闘・敵の集団移動・吹き飛ばし等の基本的な手触りを検証する。ステージごとの違いは主に景観や雰囲気とし、現段階ではステージ固有のフィールドギミックを設けない。

## 2. 草原ステージの企画要件

### 2.1 景観・世界観

- **明るく爽やかな王道ファンタジーの草原**を目指す。青空、新緑、草花などが基調。
- リアル志向ではなく、主人公リアのデザインに合うアニメ調・スタイライズド3D。
- 少しだけファンタジーらしい個性があるとよい。ただし、特定の発光植物・巨大樹などの意匠は指定しない。**具体的なデザインはCodexの提案・制作判断に委ねる。**
- 広がりを感じられる景観を重視するが、戦闘エリア外の中景・遠景は制作コストを抑える。

### 2.2 戦闘可能エリア

- **規模の仮目安：70〜100m程度（代表的な幅・直径相当）**。初期のイメージは約80m前後。最終寸法は移動速度・敵密度・カメラを用いて調整。
- 平面形状は自然な**不規則形**とする。ただし戦闘可能範囲が極端にくびれたり、戦闘の妨げになる構成は避ける。
- 内部も完全な平地にはせず、**敵の移動・密集・吹き飛ばしを阻害しない程度の緩やかな起伏**を設ける。
- 戦闘エリア中央は比較的広く開けた草地とする。大きな障害物は主に外周に寄せる。
- 敵の群れが接近・包囲し、強攻撃で吹き飛ぶ想定。カメラの視界とプレイヤーの移動しやすさを優先する。

### 2.3 外周と進入不可エリア

- **岩場・木立・川・丘（段差）を組み合わせた自然な外周**にする。
- 川は「橋が必要そう」と感じる十分な幅を持たせ、緩くカーブさせて**外周全体の約1/4〜1/3を占める境界**として使う。
- 川岸には**少し落差を設ける**。岩や植生と組み合わせ、移動できないことに納得感を持たせる。
- 残りの外周は岩、木立、段差、丘を組み合わせてつなぐ。全周を単一の境界素材で囲わない。
- **見えない壁はある程度許容する。**自然物による完全な物理的封鎖は必須としない。
- 外周の実際の当たり判定は、見た目の細かな凹凸に過度に追従させない方針。具体的な実装方法はCodex Aで検討する。

### 2.4 地面・道

- 地面は草地を主体に、土や露出した岩肌などの変化をつける。
- **マスクテクスチャを使い、草・土・岩肌などを自然にブレンド**する方向。
- **緩やかに曲がる一本道**を設ける。整備された直線道路ではなく、人や馬車が通って自然に踏み固められた土の道の印象。
- 道は戦闘エリアの**中心から少し外れた位置**を横切り、中央の広い草地を残す。
- 道幅や輪郭に自然な揺らぎを加える。両端は丘・木立の奥、または岩場・崖沿いのカーブで視界から消えるように見せる。
- 道を川の対岸に直結させる演出や橋の設置は現時点では前提にしない。

### 2.5 環境オブジェクト・植生

- 密度は**中程度**。草、花、小岩、踏み荒らされた地面、外周寄りの倒木・大岩などで変化をつける。
- 戦闘エリア内部は過密にせず、プレイヤーや敵の動線を確保する。
- 細かな草花は、**まず単体Propアセットを多数配置する方式**で制作する。
- 草花は種類・グループ単位などで**まとめて表示ON/OFF可能**な構成を目指す。将来シェーダー表現などとの比較・置き換えを検討できるようにする。
- 草花をOFFにしても、地表マテリアルだけで最低限の見た目が成立するのが望ましい。

### 2.6 中景・遠景

- 戦闘エリア外は、丘、木立、岩などで地形の続きを見せつつ、地平線の不自然さを減らす。
- さらに遠くは山並みや空などを使って開放感を表現する。細部まで作り込む必要はない。
- 360度回転するカメラから見たときの破綻を避ける。
- 具体的な遠景の作り方や見せ方はCodex Aで調査・提案する。

## 3. 制作データの基本方針（確定）

### 3.1 Blenderを配置の正本とする

**Blender上で完成したステージシーンを、見た目と配置の正本とする。** Blenderで形状・位置・回転・スケールを編集し、その結果をゲームエンジンへ出力する。

### 3.2 FBXアセットを再利用する

- ステージを巨大な1ファイルに一括結合するのではなく、**十数〜数十種類程度のFBXアセット**を組み合わせる。種類数は固定上限ではない。
- アセット分類は大きく **Terrain / Structure / Prop**。
  - **Terrain**：戦闘地形、外周の丘・地形、中景や遠景の地形など。
  - **Structure**：川岸、まとまった岩場、特徴的な大きな構造・地形要素など。草原では比率が少なくてもよい。
  - **Prop**：木、岩、草、花、低木、倒木など、繰り返し使う環境オブジェクト。
- **同一Propは同じFBXアセットを参照し、Transformを変えて繰り返し配置**する。配置数ぶんのFBX複製は作成しない。
- マスク・各種テクスチャなどは必要に応じてFBX外のリソースとして管理する。
- 水面は地面と別マテリアル・別メッシュとして扱える構成が望ましい（具体方式は要検討）。

### 3.3 JSON配置データを出力する

- Blenderの完成シーンから、**FBXアセットへの参照と各配置インスタンスのTransform（位置・回転・スケール）を記録したJSON**をエクスポートする。
- ゲームエンジンはFBXアセット群とJSONを読み込み、Blenderでの配置を再現する。
- 同じFBXを使う複数のインスタンスは同一のアセット参照に集約できるようにする。
- **JSONスキーマ、座標系・単位系の変換、回転表現、ピボット、ファイルパス規約、FBXの分割境界、マテリアル参照、コリジョン情報**はCodex Aで既存環境を調べて決定する。ここでは確定させない。
- 例として、`assets`（FBX参照一覧）と`instances`（各asset ID＋Transform）の二層データが考えられるが、これは**実装提案であり確定スキーマではない**。

## 4. 優先順位・今回の対象外

### 優先すること

1. 戦闘エリアとしての使いやすさ（移動、カメラ、敵の群れ、吹き飛ばし）。
2. 明るいファンタジー草原としての景観。
3. 川・岩・木立による自然な外周。
4. BlenderからFBX＋JSONへ再現可能に出力できること。
5. Propの再利用、草花のON/OFFなど後で修正しやすいこと。

### 今回は詳細を固定しないこと

- 特定の幻想的モチーフや個別Propの詳細デザイン。
- フィールドギミック、橋の利用、川への落下や水中移動などのゲームプレイ。
- 草花の最終的な描画最適化方式。
- 具体的なFBX個数、ポリゴン数、テクスチャ解像度、LOD・インスタンシング設計。
- JSONの最終形式、出力ツールの実装、座標変換規約。
- 敵の具体的なスポーン地点、NavMesh・コリジョンの実装方式。
- 遺跡ステージの具体要件（別途整理する）。

- Blenderシーン構造とTerrain / Structure / Propの分割単位。
